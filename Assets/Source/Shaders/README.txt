==============================================================================
  CarRace — кастомные шейдеры под WebGL Mobile / PC
==============================================================================

Все три шейдера написаны вручную в HLSL под URP (Unity 6, URP 17.4).
Сравнение с дефолтными URP-шейдерами:

  URP/Lit          — PBR, per-pixel, ~десятки multi_compile вариантов
  URP/SimpleLit    — Blinn-Phong per-pixel, ~десятки вариантов
  CarRace/*        — БЕЗ multi_compile, half-precision, SRP Batcher

Все три отрисовываются в один проход ForwardLit + один ShadowCaster,
поддерживают SRP Batcher и кастуют тени (тени НЕ принимают — это
осознанный трейдофф ради веса).

------------------------------------------------------------------------------
  CarRace/MobileLite     (файл: MobileLite.shader)
------------------------------------------------------------------------------
Минималистичный шейдер с per-vertex освещением от main directional light
(half-lambert). Без стилизации — просто очень дешёвая база.

  Свойства:
    Base Map       — основная текстура
    Base Color     — тинт
    Ambient Boost  — подсветка теневой стороны (0..1)

  ПЛЮСЫ:
    + Самый прозрачный и предсказуемый из всех трёх.
    + Реагирует на главный свет в сцене (направление, цвет, интенсивность).
    + Никаких ассетов кроме обычной текстуры.

  МИНУСЫ:
    - Без стилизации — для мрачного сеттинга нужно красить текстуры самому.
    - Per-vertex освещение: на низкополигональных мешах видны грани.

  КОГДА БРАТЬ:
    Прототипирование, объекты которые должны "честно" реагировать на солнце
    в сцене (смена времени суток через Light), мелкий пропс.

------------------------------------------------------------------------------
  CarRace/MobileStylized (файл: MobileStylized.shader)
------------------------------------------------------------------------------
Расширение MobileLite со стилизацией под мрачный сеттинг.
Всё дополнительно — per-vertex или одной командой во фрагменте.

  Свойства:
    Base Map, Base Color           — как обычно
    Shadow Tint                    — цвет тёмной стороны (вместо чёрного)
    Ambient Boost                  — подъём чёрных
    Toon Steps                     — 1 = плавно, 2..6 = toon-полосы
    Color Grade                    — глобальный мульти-тинт (болезненный окрас)
    Desaturation                   — выцветает мир (0..1)
    Rim Color / Power / Intensity  — дешёвый fresnel-силуэт

  ПЛЮСЫ:
    + Стилизация настраивается одним материалом, без правки текстур.
    + Двухтональная заливка (Shadow Tint != чёрный) сразу даёт настроение.
    + Toon-полосы — узнаваемый "гриттовый" вид.
    + Реагирует на главный свет сцены.

  МИНУСЫ:
    - Чуть дороже MobileLite (rim + grade + desaturate).
    - Per-vertex освещение: те же ограничения на low-poly.
    - Стилизация привязана к направлению света — если двигать солнце,
      картинка меняется.

  КОГДА БРАТЬ:
    Машины, основные пропсы, окружение — когда нужна готовая стильная
    картинка с минимальной настройкой и сохранением реакции на свет.

------------------------------------------------------------------------------
  CarRace/MobileMatcap   (файл: MobileMatcap.shader)
------------------------------------------------------------------------------
ПОЛНОСТЬЮ UNLIT шейдер. Никаких обращений к рантайм-свету.
Иллюзия освещения = MatCap-текстура (sphere) + hemisphere (sky/ground) + rim.

  Свойства:
    Base Map, Base Color           — как обычно
    MatCap                         — sphere-текстура с запечённым светом
    MatCap Tint / Strength         — окрас и сила matcap'а
    Sky Color / Ground Color       — hemisphere-амбиент по нормали Y
    Rim Color / Power / Intensity  — fresnel-силуэт
    Color Grade / Desaturation     — финальный mood-проход

  ПЛЮСЫ:
    + САМЫЙ ЛЁГКИЙ из трёх — нет Lighting.hlsl, нет GetMainLight, нет MAD'ов
      под half-lambert. На фрагмент: 2 sample + normalize + lerp + matmul.
    + Стилизация полностью контролируется художником через matcap-текстуру —
      студийный/мрачный/токсичный лук получается сменой одной картинки.
    + Картинка не зависит от позиции солнца — стабильное настроение.

  МИНУСЫ:
    - Не реагирует на свет вообще — никаких смен времени суток.
    - MatCap "прилеплен" к камере: вращая камеру вокруг объекта,
      видишь как свет "поворачивается" вместе с ней.
    - Нужно подготовить matcap-текстуру (см. ниже).

  КОГДА БРАТЬ:
    Основной шейдер для мрачного зомби-сеттинга. Когда нужен фиксированный
    арт-дирекшн, контроль через ассеты, максимальная производительность.


==============================================================================
  Как пользоваться MatCap
==============================================================================

ЧТО ТАКОЕ MATCAP:
  Это квадратная текстура (обычно 256x256 или 512x512), на которой нарисована
  сфера, как будто она лежит перед камерой и освещена нужным светом.
  Шейдер сэмплит её по UV = view-space normal.xy * 0.5 + 0.5. Результат —
  объект выглядит лит, хотя реального света в сцене нет.

КАК СДЕЛАТЬ MATCAP:
  Вариант 1 (быстрый): найти готовый набор matcap-текстур —
    например, https://github.com/nidorx/matcaps (общественные, MIT).
    Для зомби-сеттинга бери холодные/болезненные палитры:
      • "Clay" мрачно-серый
      • тёмно-зелёные с грязным highlight'ом
      • асфальтово-чёрные с холодным rim

  Вариант 2 (Blender, 5 минут):
    1. Создай Sphere, поставь Shade Smooth.
    2. Камера орто, смотрит ровно вдоль Z на сферу.
    3. Поставь свет(а) под нужное настроение (sun + fill).
    4. Рендер 512x512, фон чёрный.
    5. Сохрани PNG, импортируй в Unity.

  Вариант 3 (фото): сфотографируй металлический/глянцевый шар при нужном свете
  и обрежь до квадрата.

НАСТРОЙКИ ИМПОРТА В UNITY (важно!):
  Texture Type:    Default
  sRGB:            ON (если matcap содержит цвет, не "data")
  Alpha Source:    None
  Wrap Mode:       Clamp           <-- ОБЯЗАТЕЛЬНО, иначе на краях шов
  Filter Mode:     Bilinear
  Compression:     Normal Quality
  Generate Mips:   OFF (текстура читается ровно)
  Max Size:        256 или 512     (больше не нужно, экономь память на mobile)

ПОВЕДЕНИЕ ПРИ ВРАЩЕНИИ КАМЕРЫ:
  MatCap живёт в view-space, поэтому "освещённая" сторона matcap'а всегда
  привязана к камере. При наклоне камеры вверх/вниз освещение на объекте
  визуально смещается в противоположную сторону — это нормально и так
  работают все matcap'ы (Blender Sculpt, ZBrush и т.д.).

  Если на silhouette-краях видна тёмная "окантовка" / шов — это не баг
  шейдера, а особенность matcap-текстуры: на её краях за пределами
  нарисованной сферы остался тёмный фон. Лечится двумя способами:
    1) Перерисовать matcap так, чтобы освещённая сфера занимала ВСЮ
       текстуру (без чёрного фона по углам). Sphere map маппинг в шейдере
       компенсирует большую часть проблемы, но не отрицательное альбедо
       в углах текстуры.
    2) Слегка увеличить нарисованную сферу в matcap-текстуре, чтобы
       её край был ярче чёрного фона.

КАК СОЗДАТЬ МАТЕРИАЛ:
  1. Project → Create → Material → назови, например, "M_Car_Matcap".
  2. В инспекторе → Shader → CarRace/MobileMatcap.
  3. В слот MatCap перетащи свою sphere-текстуру.
  4. В Base Map — основная текстура (albedo) машины/пропа.
  5. Подкрути:
       MatCap Strength = 0.8..1.2   (главная сила matcap-блика)
       Sky/Ground      = тон неба и земли в твоей сцене
       Rim Intensity   = 0.4..0.8   (силуэт в темноте)
       Desaturation    = 0.3..0.5   (мрачнее)
       Color Grade     = чуть зелёно-жёлтый для трупного окраса

==============================================================================
  MatCap Baker — встроенный генератор matcap-текстур
==============================================================================

В проекте есть редакторный инструмент для запекания собственных matcap'ов
прямо из Unity. Файлы:

  Assets/Source/Shaders/Tools/Editor/MatcapBaker.cs        — MonoBehaviour
  Assets/Source/Shaders/Tools/Editor/MatcapBakerEditor.cs  — UI + MenuItem

ПЕРВЫЙ ЗАПУСК:
  Меню Unity: Tools -> CarRace -> Open MatCap Baker Scene
  При первом запуске создаётся сцена Assets/Source/Shaders/Tools/MatcapBakerScene.unity
  + материал MatcapBakeSphere.mat (URP/Lit, белый). При повторном — просто
  откроется существующая сцена с твоими настройками.

ШАГИ ЗАПЕКАНИЯ:
  1. Сразу после открытия сцены автоматически выделяется GameObject
     "MatcapBaker" и открывается окно Game View — в Game View видишь то,
     что попадёт в matcap.
  2. В иерархии выдели KeyLight / FillLight / RimLight по очереди и
     крути их rotation / color / intensity. Game View обновляется онлайн.
  3. (опционально) Выдели "BakeSphere" -> в инспекторе материал
     MatcapBakeSphere — меняй Base Color / Metallic / Smoothness, чтобы
     получить нужный лук поверхности (matte / chrome / wet / waxy).
  4. Снова выдели "MatcapBaker". В инспекторе:
       Resolution = 256 / 512 / 1024 (для WebGL хватает 256)
       File Name  = Matcap_Foggy_Morning (без .png)
  5. Жми большую зелёную кнопку "BAKE MatCap → PNG".
     PNG сохранится в Assets/Source/Shaders/Matcaps/ и пингнется в Project.

  Все шаги дублируются прямо в инспекторе MatcapBaker — синяя HelpBox сверху.

ИМПОРТНЫЕ НАСТРОЙКИ:
  Применяются автоматически если включено "Apply Import Settings":
    Wrap Mode = Clamp, Mips = OFF, sRGB = ON, Alpha Source = None.
  Это критично — без Clamp на краях шва не избежать.

СОВЕТЫ:
  • Один и тот же matcap можно перепекать в разных настройках света — просто
    меняй File Name перед каждым жмаком, иначе перезапишет.
  • Чтобы получить мрачный лук — приглуши Fill (0.1..0.2), увод Key в
    холодный тон (синевато-серый), Rim сделай ядовито-зелёным.
  • Для chrome-like / mokushi look — поставь Key белым, Fill — холодным,
    Rim — оранжевым (контровой свет от заката).
  • После запекания материал на BakeSphere сам по себе не меняется —
    можешь итерировать дальше без потери настроек.

ВНИМАНИЕ:
  Скрипты лежат в Editor/ — компилятся только в редакторе, в WebGL-сборку
  не попадают. Соответственно сцена MatcapBakerScene.unity в build НЕ
  включается (если случайно попала в Build Settings — убери её оттуда).

==============================================================================
  Occluder-варианты: растворение / срез объектов перед игроком
==============================================================================

Камера стоит сзади-сверху (изометрия). Объекты, попавшие МЕЖДУ игроком и
камерой, мешают видеть персонажа. Для этого есть три шейдера-копии:

  CarRace/MobileLiteOccluder       (MobileLiteOccluder.shader)
  CarRace/MobileStylizedOccluder   (MobileStylizedOccluder.shader)
  CarRace/MobileMatcapOccluder     (MobileMatcapOccluder.shader)

Каждый ПОЛНОСТЬЮ идентичен своему базовому шейдеру (картинка, свет, стиль),
но во фрагменте дополнительно вызывает общий код из OccluderFade.hlsl.

ДВА РЕЖИМА (переключатель _FoundationMode в материале, [ToggleUI]):
  • Foundation OFF — объект целиком плавно РАСТВОРЯЕТСЯ дизером, когда
    перекрывает игрока (универсально: деревья, столбы, мелкие строения).
  • Foundation ON  — у объекта прячется только ВЕРХ, остаётся основание
    ("фундамент"). Высота сохраняемой части — _KeepHeight (мировые ед.),
    мягкость среза — _FoundationEdge. Для домов/крупных строений.

  ВАЖНО: "основание" отсчитывается от ПИВОТА объекта (его мировой Y).
  Предполагается, что пивот строения стоит на земле. Если пивот в центре
  меша — подними _KeepHeight на половину высоты или сдвинь пивот в импорте.

КАК ЭТО РАБОТАЕТ (дёшево и без CPU per-object):
  • Растворение — упорядоченный дизер (Interleaved Gradient Noise), один
    clip во фрагменте. Объект остаётся в Opaque-очереди: НЕТ alpha-blending,
    НЕТ overdraw-штрафа, НЕТ пересортировки прозрачности. SRP Batcher живёт.
  • Детект "между игроком и камерой" — чисто шейдерный, через 2 глобали:
      _OccluderPlayer (xy=экранная позиция игрока, z=eye-depth, w=вкл)
      _OccluderParams (x=радиус зоны, y=мягкость, z=depth bias)
    Фрагмент прячется, если он 1) близко к игроку на экране И 2) ближе к
    камере, чем игрок. Никаких multi_compile, оба режима — branchless (lerp).
  • Глобали выставляет раз в кадр OccluderFadeDriver.cs
    (Assets/Source/Scripts/Helpers/OccluderFadeDriver.cs).

НАСТРОЙКА:
  1. Повесь OccluderFadeDriver на постоянный объект (удобно — на камеру).
  2. Укажи Player (Transform) и Camera. Подкрути:
       Player World Offset    = (0,1,0) — центр зоны на теле, не в ногах
       Radius Screen Fraction = 0.10..0.15 — размер "окна" вокруг игрока
       Softness Fraction      = 0.04..0.06 — мягкость края
       Depth Bias             = 0.3..1.0 — чтобы пол под игроком не резался
  3. На перекрывающих объектах поставь материал на *Occluder-шейдере.
     Для домов включи Foundation mode и задай Keep Height.

ЗАМЕЧАНИЯ:
  • Тени (ShadowCaster) НЕ трогаются — скрытый/срезанный объект всё равно
    кастует полную тень (контакт с землёй читается). Если не нужно — выключи
    Cast Shadows на конкретном Renderer.
  • Зона круглая (есть поправка на аспект экрана через _ScreenParams).
  • Стоимость относительно базы: ~десяток ALU + один clip на фрагмент.


==============================================================================
  Общие замечания
==============================================================================

ВСЕ ТРИ ШЕЙДЕРА:
  • Поддерживают SRP Batcher (CBUFFER_START(UnityPerMaterial)).
  • Кастуют тени через ShadowCaster pass.
  • НЕ принимают тени на себя — это сознательный выбор ради веса.
    Если нужны тени на объекте — лучше взять URP/SimpleLit для этого
    конкретного материала.
  • НЕ поддерживают: normal map, additional lights, lightmaps,
    reflection probes, fog, vertex color, GPU instancing keywords.

КАК ПРИМЕНИТЬ КО ВСЕМ ОБЪЕКТАМ:
  1. Создай материал на нужном шейдере (например, M_Default_Matcap).
  2. Project → правой кнопкой на Assets/Source → Find References / Replace
     материал на всех Mesh Renderer'ах.
  Либо: выдели объекты в сцене и перетащи материал на них в инспекторе.

ПОРЯДОК ВЫБОРА:
  Хочешь максимум перформанса и стиль через ассеты   → MobileMatcap
  Хочешь стиль + реакцию на солнце                   → MobileStylized
  Хочешь честное освещение и нулевую стилизацию       → MobileLite
